# 管理者向けセットアップ手順

受講生に配る前に、管理者（あなた）が一度だけ行う設定です。
所要時間はだいたい30〜40分です。順番どおりに進めてください。

必要なもの:

- Googleアカウント（GAS・スプレッドシート・GCPで使用）
- Gemini APIキー（https://aistudio.google.com/apikey で発行）
- GitHubアカウント（ホスティング用）

> v1・v2からの更新の場合: STEP 2 の「Code.gsを貼り直して新バージョンでデプロイ」、STEP 2.5 のキー発行、STEP 3 の push で完了です。
> config.js・OAuthクライアントID・辞書シートはそのまま使えます。

---

## STEP 1: チーム共有辞書スプレッドシートを作成

1. Googleドライブで新しいスプレッドシートを作成（名前は「文字起こしするちゃん辞書」など何でもOK）
2. 中身は空のままでOK（1行目のヘッダーは初回アクセス時に自動で作られます）
3. URLからスプレッドシートIDを控える
   `https://docs.google.com/spreadsheets/d/【この部分がID】/edit`

※このシートはあなたのドライブに置いたままでOK。受講生はGAS経由で読み書きするので、共有設定は不要です。

## STEP 2: GAS（バックエンド）をデプロイ

1. https://script.google.com → 「新しいプロジェクト」
2. `gas/Code.gs` の中身をエディタに貼り付けて保存
3. 左メニュー「プロジェクトの設定」→ 下部の「スクリプト プロパティ」で以下を追加

   | プロパティ名 | 値 |
   |---|---|
   | `GEMINI_API_KEY` | あなたのGemini APIキー |
   | `DICT_SHEET_ID` | STEP 1のスプレッドシートID |
   | `MODEL` | （任意）省略時は `gemini-2.5-flash` |

4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
5. 承認画面が出たら許可する
6. 表示された **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）を控える
7. そのURLをブラウザで開くと、設定状況（キー・辞書シート・モデル）がJSONで表示されます。
   `"GEMINI_API_KEY": "設定済み"`, `"DICT_SHEET_ID": "設定済み（開けました）"` になっていればOK

> ⚠ APIキーはスクリプトプロパティにだけ置きます。フロントエンドのコードやGitHubには絶対に書かないでください。
> ⚠ Code.gsを修正したときは「デプロイを管理」→ 既存デプロイの編集 → バージョン「新バージョン」で更新します（URLが変わりません）。

## STEP 2.5: ライセンスキーを発行する

利用者は、URLとライセンスキーのセットで使います。キーは1人に1つ発行します。

1. GASエディタ上部の関数選択で `issueLicenseKeys` を選び「実行」
   → STEP 1 のスプレッドシートに「ライセンス」タブが自動で作られます（初回は承認画面が出たら許可）
2. 「ライセンス」タブの **B列に名前** を書く（まず自分の名前。受講生は1行に1人ずつ）
3. もう一度 `issueLicenseKeys` を実行 → A列に `MOJI-XXXX-XXXX-XXXX` 形式のキーが入り、C列が「有効」になります
4. GASのウェブアプリURLを開いて `"LICENSE": "「ライセンス」タブOK（発行済みキー ○件）"` と出ればOK

| 列 | 意味 |
|---|---|
| A キー | 自動発行。手で書き換えない |
| B 名前 | 誰に渡したか。画面右上に「○○ さん」と表示されます |
| C 状態 | 「有効」／「停止」。停止にすると5分以内に使えなくなります |
| D 有効期限 | 例: 2026/12/31（その日の終わりまで有効）。空欄＝無期限 |
| E 月の上限(分) | 文字起こしできる音声の長さの月間上限。空欄＝無制限 |
| F〜H | 集計月・今月の利用(分)・最終利用。自動で入ります |
| I メモ | 自由欄 |

> ⚠ このスプレッドシートにはキーが並ぶので、他人と共有しないでください（受講生はGAS経由でしか触れません）。
> ⚠ キーが漏れた・使い回されていると感じたら、その行を「停止」にして、新しい行で発行し直します。
> 「利用ログ」タブで、誰がいつ何分使ったかを確認できます。

### モデルの選び方

| MODEL | 特徴 |
|---|---|
| `gemini-2.5-flash`（既定） | 速い・安い。講座・会議の文字起こしには十分な精度 |
| `gemini-2.5-pro` | より高精度だが数倍遅く、料金も約10倍。専門用語が多い内容向け |
| それ以降の新しいモデル | プロパティを書き換えるだけで切り替わります（思考の設定は 2.5 flash 系だけに適用されるので、他モデルでも壊れません） |

## STEP 3: GitHub Pagesで公開

1. GitHubで新しいリポジトリを作成（公開リポジトリでOK。APIキーは含まれません）
2. このフォルダの中身一式をpush（`.github/workflows/deploy.yml` が入っていれば自動デプロイされます）
3. リポジトリの Settings → Pages → Source を「GitHub Actions」にする
4. 公開URL `https://あなたのユーザー名.github.io/リポジトリ名/` を控える

## STEP 4: GCPでOAuthクライアントIDを発行（Googleドライブ保存用・任意）

> 「Googleドライブに保存」ボタンのための設定です。コピーとtxt保存だけでよければ、このSTEPは飛ばして
> `OAUTH_CLIENT_ID` を空のままにしてください（保存ボタンが非表示になります）。

1. https://console.cloud.google.com → 新しいプロジェクトを作成（名前は「mojiokoshi-drive」など）
2. 「APIとサービス」→「ライブラリ」で以下を有効化
   - **Google Drive API**
   - **Google Sheets API**
3. 「APIとサービス」→「OAuth同意画面」
   - User Type: **外部** → 作成
   - アプリ名・サポートメール・デベロッパー連絡先を入力して保存
   - スコープの追加は**不要**（アプリ側が実行時に要求します。使うのは `drive.file` ＝「このアプリが作成したファイルのみ」の非センシティブなスコープなので、Googleの審査は不要です）
   - 「公開ステータス」を**本番環境に公開**する（テストのままだと登録したテストユーザーしかログインできません）
4. 「認証情報」→「認証情報を作成」→「OAuthクライアントID」
   - アプリケーションの種類: **ウェブアプリケーション**
   - 承認済みのJavaScript生成元に以下を追加
     - `https://あなたのユーザー名.github.io`（STEP 3のドメイン部分。パスは含めない）
     - `http://localhost:8000`（ローカル動作確認用・任意）
   - 「リダイレクトURI」は空でOK
5. 発行された **クライアントID**（`xxxx.apps.googleusercontent.com`）を控える

## STEP 5: config.js に設定を書き込む

`js/config.js` を開いて埋め、pushします（`OAUTH_CLIENT_ID` はDrive保存を使う場合だけ）。

```js
window.APP_CONFIG = {
  GAS_URL: 'https://script.google.com/macros/s/XXXX/exec',   // STEP 2のURL
  OAUTH_CLIENT_ID: 'xxxx.apps.googleusercontent.com',        // STEP 4のID
};
```

## STEP 6: 動作確認

1. 公開URLを開く → 自分のライセンスキーを入力 →「はじめる」（右上に自分の名前が出ればOK）
   でたらめなキーでは入れないこと、ページを再読み込みしても入力なしで入れることも確認
2. 短いMP3（1〜2分）で文字起こし → 結果表示 → 「Googleドライブに保存」→ Googleログイン → 保存
3. 自分のドライブに「文字起こしするちゃん」フォルダとスプレッドシートができていればOK
4. 結果のテキストを1語直して「修正を辞書に学習」→ チーム辞書タブに反映されていればOK
5. もう一度同じファイルで実行し、辞書が効いていることを確認
6. できれば20分以上のMP4かMOVでも1回試す（ファイル情報に「音声だけを抜き出して送ります」と出て、区間 (1/2) (2/2) と進めばOK）

確認できたら、公開URLと**その人専用のライセンスキー**をセットで受講生に渡してください。受講生側の設定は一切不要です。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 「ライセンスキーが正しくありません」 | 台帳のA列と一致しているか確認。全角・小文字・空白は自動で直るので、桁の写し間違いが大半です |
| 正しいキーなのに入れない | C列が「停止」でないか、D列の期限が過ぎていないか確認 |
| 「今月の利用上限に達しました」 | E列の上限を増やすか空欄にする。翌月1日に自動でリセットされます |
| 更新したら全員使えなくなった | v2.1からキー必須です。STEP 2.5 でキーを発行して配ってください |
| Drive保存で「アクセスをブロック」と出る | OAuth同意画面が「テスト」のまま → 本番環境に公開する。またはJavaScript生成元のURL間違い |
| 「GAS_URLが設定されていません」 | config.jsの設定漏れ、またはpush忘れ |
| 文字起こしで「GEMINI_API_KEYが設定されていません」 | GASのスクリプトプロパティを確認 → デプロイを新バージョンで更新。GASのURLを開いて設定状況を確認できます |
| 「不明なaction」と出る | GASが古いまま → Code.gsを貼り直して新バージョンでデプロイ |
| 保存で403エラー | GCPでDrive API / Sheets APIが有効になっているか確認 |
| 辞書が読み書きできない | `DICT_SHEET_ID` の値（URL全体ではなくID部分）を確認 |
| Gemini APIエラー (429) | 無料枠の回数制限。少し待つか、Google AI Studioで課金を有効にする |
| 「ファイル全体を送って範囲指定で処理します」と出る | その形式（WebMなど）は音声だけの切り出しに非対応。動作はしますが遅く、1時間超の動画は失敗することがあります。MP4/MOV/MP3/M4Aに変換すると速く確実です |
| 結果の一部が途切れている・重複している | 「区間の出力が上限で途切れた」と出た場合は、その区間の話が極端に速いか長い可能性があります。ヒントを付けて再実行してください |

## コストの目安

v2は「音声だけを1回分」入力するので、Gemini 2.5 Flashなら3時間の音声・動画1本あたりおおよそ数十円です
（音声入力 ≒ 1時間あたり11万トークン。整形・要約のテキスト分を含めても100万トークン未満）。
全受講生の利用があなたのAPIキーに課金されるので、Google AI Studioの使用量ページをときどき確認してください。
上限を掛けたくなった場合は、GCP側の「割り当て」でAPIキーの1日あたりリクエスト数を制限できます。
